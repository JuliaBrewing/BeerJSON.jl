Validating and writing

The constructors of the types only convert the values to the types of their fields. They enforce the structure of the schema (the types of the properties, the required properties, the enumeration types), but not its constraints, such as the values allowed for an enumeration, or the minimum number of steps of a mash. This keeps them cheap, which matters for the conversions from the working types of BrewQuiver.jl.

The checks of the constraints are done by validate, violations and isvalid, and before writing.

using BeerJSON

file = joinpath(pkgdir(BeerJSON), "test", "samples", "converted", "Kolsh.json")
doc = readjson(BeerJSONParser, file)
isvalid(doc)
true

A unit that is not one of BeerJSON is accepted by the constructor...

v = VolumeType(unit = "litre", value = 20)
VolumeType: 20.0 litre

...but it is not valid:

isvalid(v)
false
foreach(println, violations(v))
unit: invalid value "litre" for `VolumeUnitType`; allowed values are "ml", "l", "tsp", "tbsp", "floz", "cup", "pt", "qt", "gal", "bbl", "ifloz", "ipt", "iqt", "igal", "ibbl"

violations lists the problems found in a value and in the values nested in it, with their locations:

recipe = only(doc.beerjson.recipes)
bad = setfields(doc; beerjson = setfields(doc.beerjson;
    recipes = [setfields(recipe; batch_size = v)]))
foreach(println, violations(bad))
beerjson.recipes[1].batch_size.unit: invalid value "litre" for `VolumeUnitType`; allowed values are "ml", "l", "tsp", "tbsp", "floz", "cup", "pt", "qt", "gal", "bbl", "ifloz", "ipt", "iqt", "igal", "ibbl"

validate(x) returns x if it is valid, and else throws a SchemaValidationError listing the problems:

try
    validate(bad)
catch e
    showerror(stdout, e)
end
SchemaValidationError: 1 value does not conform to the schema:
  beerjson.recipes[1].batch_size.unit: invalid value "litre" for `VolumeUnitType`; allowed values are "ml", "l", "tsp", "tbsp", "floz", "cup", "pt", "qt", "gal", "bbl", "ifloz", "ipt", "iqt", "igal", "ibbl"

Writing

writejson(file, x) and tojson(x) validate before writing, so invalid documents are not written:

try
    tojson(bad)
catch e
    showerror(stdout, e)
end
SchemaValidationError: 1 value does not conform to the schema:
  beerjson.recipes[1].batch_size.unit: invalid value "litre" for `VolumeUnitType`; allowed values are "ml", "l", "tsp", "tbsp", "floz", "cup", "pt", "qt", "gal", "bbl", "ifloz", "ipt", "iqt", "igal", "ibbl"

Valid documents are written with the same content as they were read:

using JSON

JSON.parse(tojson(doc)) == JSON.parse(read(file, String))
true
writejson("Kolsh-copy.json", doc)

The validation can be skipped with validate = false, as in tojson(bad; validate = false).

Reading is not validated, as it would slow it down: use validate(readjson(BeerJSONParser, file)) for that.

Formats

Strings with a format in the schema, such as dates, are checked too. JSON Schema treats format as an annotation by default, so these checks can be turned off with check_formats!(false) (and back on with check_formats!(true)).
