API

BeerJSON — Module
BeerJSON

Julia types for reading, writing and validating BeerJSON 1.0.1 documents.

The types are generated from the official JSON Schema by JSONSchema2Types.jl, into the submodule BeerJSON.BeerJSONTypes, whose names are all re-exported. The root of a document is BeerJSONParser (also RootType).

With Unitful.jl and UnitfulBrewing.jl loaded, the extension BeerJSONUnitfulExt adds quantity, unitful_unit, unit_table, unsupported_units and constructors of the measurement types from quantities.

Changing values

BeerJSON.BeerJSONTypes.setfields — Function
setfields(x; kwargs...)

Return a copy of the generated struct x with the fields given as keyword arguments replaced. The new values are converted and validated as by the constructor, so plain values work: setfields(volume; value = 40), setfields(recipe; batch_size = (unit = "l", value = 40)). Use the Julia names of the fields (e.g. first_name for a JSON property first-name).

For nested changes, the generated structs also work with Accessors.jl: @set recipe.batch_size.value = 40.

BeerJSON.BeerJSONTypes.violations — Function
violations(x) -> Vector{String}

Check x (a value of a generated type, or a vector, dict or tuple of them), and every value nested in it, against all the constraints of the schema, whether or not the checks were on when they were created (see checks!). Returns the problems found, one per invalid value (the first problem of each), with its location, e.g. "batch_size:valueinVolumeTypemust be ≥ 0, got -1.0". The location uses the JSON names of the properties and 1-based indices of the items: recipes[1].batch_size.

check_formats!(flag::Bool)

Enable or disable the validation of the format keyword. Enabled by default. Unitful quantities

These need Unitful.jl and UnitfulBrewing.jl to be loaded (see Unitful extension).

BeerJSON.quantity — Function
quantity(x)

The value of the measurement x (a VolumeType, MassType, TemperatureType, ... with fields unit and value) as a Unitful quantity, in the unit of the BeerJSON value.

quantity(VolumeType(unit = "gal", value = 5))     # 5.0 gal
quantity(TemperatureType(unit = "C", value = 67))  # 67.0 °C

PercentType gives a quantity in percent, AcidityType a logarithmic pH⁺ value, and UnitType (counts in "each", "pkg", ...) a plain number.

Throws an ArgumentError for a unit that has no Unitful counterpart (see unsupported_units).

Requires Unitful.jl and UnitfulBrewing.jl to be loaded.

source

The Unitful unit of the BeerJSON unit u, a value of a unit enumeration such as VolumeUnitType("l"), or given by the enumeration type U and the string s, as in unitful_unit(VolumeUnitType, "l").

Checks in the constructors

The generated module also has checks!, checks and with_checks, which turn on or off the checks of the constraints in the constructors of the types. They only apply to modules generated with the checks in the constructors: here, the types are generated with the validation in a separate file (validation = :separate), so the constructors never check the constraints, and validate, violations, isvalid, tojson and writejson always do. They are not exported.

BeerJSON.BeerJSONTypes.checks! — Function
checks!(flag::Bool)

Turn on or off the checks of the constraints of the schema when values of the generated types are created (by their constructors, setfields, fromjson...). They are on by default (unless the module was generated with checks = false).

With the checks off, values are only converted to the types of their fields, which still enforce the structure of the schema (the types of the properties, required properties, the properties allowed, enumeration types), but not its constraints (minimum, pattern, the values of enumerations, minItems, oneOf...), for speed. Check the values later with validate, which tojson and writejson call when the checks are off. A JSON value read into a union of generated types (from oneOf or anyOf) is still checked, to choose its type.

The setting is global (shared by all tasks); see with_checks to change it temporarily. Returns the previous setting.

source
