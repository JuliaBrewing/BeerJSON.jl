Unitful extension

With Unitful.jl and UnitfulBrewing.jl loaded, the package extension BeerJSONUnitfulExt maps the units of BeerJSON to Unitful units, to display the values of a document as quantities, for scripting, and as building blocks for the conversions of BrewQuiver.jl. It has no working types, internal units or calculations: those belong in BrewQuiver.jl.

UnitfulBrewing is not registered yet: install it with Pkg.add(url = "https://github.com/JuliaBrewing/UnitfulBrewing.jl").

using BeerJSON
using Unitful, UnitfulBrewing

Quantities

quantity(x) gives the value of a measurement (any of the types with a unit and a value, such as VolumeType, TemperatureType or GravityType) as a Unitful quantity, in the unit of the file:

file = joinpath(pkgdir(BeerJSON), "test", "samples", "converted", "Kolsh.json")
recipe = only(readjson(BeerJSONParser, file).beerjson.recipes)
quantity(recipe.batch_size)
19.0028767 L
uconvert(u"gal", quantity(recipe.batch_size))
5.0200289385478385 gal

From quantities

The measurement types can be constructed from quantities, with the value written in a BeerJSON unit given by the keyword argument unit:

VolumeType(5u"gal"; unit = "l")
VolumeType: 18.9271 l

Without unit, the BeerJSON unit of the unit of the quantity is used if there is one, and else a default unit ("l" for volumes, "kg" for masses, "min" for times, "C" for temperatures, "sg" for gravities, "SRM" for colors, "ppm" for concentrations, ...):

VolumeType(5u"gal"), VolumeType(0.02u"m^3")
(VolumeType(VolumeUnitType("gal"), 5.0), VolumeType(VolumeUnitType("l"), 20.0))

They work with other numeric types too, as VolumeType{BigInt, BigFloat}(q). So the values round trip, T(quantity(x)) == x:

VolumeType(quantity(recipe.batch_size)) == recipe.batch_size
true

Temperatures in °C and °F are affine units, and are converted as such:

TemperatureType(67u"°C"; unit = "F")
TemperatureType: 152.6 F

TimeType stores whole numbers (the schema has integers there), so a time must be a whole number in the chosen unit:

TimeType(1.5u"hr"; unit = "min")
TimeType: 90 min

Equivalences: gravity, concentration and carbonation

Specific gravity and degrees Plato (or Brix) measure different things, and are not related by a factor: UnitfulBrewing gives them different dimensions and converts between them with equivalences (from UnitfulEquivalences.jl). The constructors use them when the dimensions of the quantity and of the BeerJSON unit differ, with SugarGravity() by default for gravities, which converts by $°P = 259 (1 - 1/\mathrm{sg})$:

GravityType(1.040u"sg"; unit = "plato")
GravityType: 9.96154 plato
GravityType(12u"°P"; unit = "sg")
GravityType: 1.04858 sg

Another equivalence can be given with the keyword argument equivalence, such as SugarGravityQuad(), the quadratic formula of UnitfulBrewing:

GravityType(1.040u"sg"; unit = "plato", equivalence = SugarGravityQuad())
GravityType: 9.99224 plato

Since specific gravities are dimensionless, a gravity is only built from quantities in sg or in gravity units gu, so that a percentage or another ratio is not silently taken as a specific gravity:

GravityType(40u"gu")
GravityType: 1.04 sg

Concentrations in ppm or ppb and in mg/l are converted with DensityConcentration(), which takes 1 ppm as 1 mg/l:

ConcentrationType(150u"mg/L"; unit = "ppm")
ConcentrationType: 150.0 ppm

Carbonation in volumes of CO₂ per volume of beer and in g/l is converted with CarbonationDensity(), which takes 1 vols as 1.977 g/l (the density of CO₂ at 0 °C and 1 atm):

CarbonationType(2.5u"vols"; unit = "g/l")
CarbonationType: 4.9425 g/l

Colors in EBC are proportional to SRM, and degrees Lovibond are affine in SRM, so these are plain unit conversions in UnitfulBrewing:

ColorType(10u"SRM"; unit = "EBC"), ColorType(10u"SRM"; unit = "Lovi")
(ColorType(ColorUnitType("EBC"), 19.7), ColorType(ColorUnitType("Lovi"), 7.943304296471283))

Percentages, counts and pH

  • Percentages (PercentType, unit "%") are quantities in Unitful's percent, so that uconvert(NoUnits, 5u"percent") == 0.05. PercentType is built from dimensionless quantities (5u"percent", 0.5u"permille"), not from plain numbers, which would be ambiguous (0.05 or 5%?).
  • Counts (UnitType, with units "1", "unit", "each", "dimensionless" and "pkg") stay plain numbers: quantity gives the number, and UnitType(2; unit = "pkg") builds one, with the unit "1" by default.
  • pH (AcidityType) is a logarithmic scale: quantity gives a pH⁺ value of UnitfulBrewing, and AcidityType(5.4u"pH⁺") builds one.
quantity(PercentType(unit = "%", value = 4.5)), quantity(UnitType(unit = "pkg", value = 2)),
quantity(AcidityType(unit = "pH", value = 5.4))
(4.5 %, 2.0, 5.4 pH⁺)

The tables

unit_table(U) gives the Unitful unit of each BeerJSON unit of the unit enumeration U (and unsupported_units(U) the units without one, with the reason: none, currently). unitful_unit gives the unit of a single BeerJSON unit:

unitful_unit(VolumeUnitType("gal")), unitful_unit(GravityUnitType, "plato")
(gal, °P)

Some notes on the choices:

  • Volumes in tsp, tbsp, floz, cup, pt, qt and gal are US customary units (the cup is 8 US fluid ounces), and bbl is the US beer barrel of 31 US gallons. The imperial volumes are ifloz, ipt, iqt, igal, and ibbl, the imperial beer barrel of 36 imperial gallons.
  • ppm and ppb are Unitful's own units.
  • In the specific heats, "Cal/(g C)" is taken as the calorie (4.184 J) per gram and kelvin, so that water has a specific heat of about 1 in it as in "BTU/(lb F)", and the C and F are differences of temperatures (kelvin and rankine).
  • "brix" is Brix of UnitfulBrewing, which takes it as equal to degrees Plato.

Unsupported units

Every unit of BeerJSON 1.0.1 has a Unitful counterpart. Should a unit be missing in UnitfulBrewing (say, in a later version of the schema), it would be listed by unsupported_units(U), with the reason, and using it would throw an ArgumentError.
